Interactive Demo Walkthrough Guide

To effectively demonstrate the power and safety of the Archival Engine, we have designed a specific narrative flow using the three provided simulated databases (CRM, OMS, and FIN).

Phase 1: Infrastructure Setup (The Control Plane)

  1. Navigate to Infrastructure -> Connection Profiles:

    • Create three profiles pointing to the simulated databases: PG-CRM-Primary, PG-OMS-East, and MSSQL-FIN-Core.

  2. Navigate to Infrastructure -> Target Profiles:

    • Create a Target Profile named GCS-Cold-Archive pointing to your designated Google Cloud Storage bucket (e.g., gs://archon-demo-archive/).

  3. Navigate to Target Groups:

    • Create a logical cluster named Global Production Systems. Assign all three Connection Profiles to this group.

Phase 2: Defining the Business Logic (Policies)

  1. Navigate to Policies -> Archival Policies:

    • We will create two distinct policies to demonstrate flexibility:

    • Policy A (Standard 7-Year Purge):

      • Target Setup: Map the execution target to the GCS-Cold-Archive profile.

      • Extraction Logic: WHERE created_dt < DATEADD(year, -7, GETDATE()) (adjusted for Postgres syntax as needed).

      • Target Tables: [ "support_tickets", "orders", "transactions" ].

    • Policy B (Aggressive Log Purge):

      • Target Setup: Map to GCS-Cold-Archive.

      • Extraction Logic: WHERE interaction_dt < DATEADD(month, -6, GETDATE()).

      • Target Tables: [ "interactions", "audit_logs" ].

Phase 3: The Execution & Live Visualization (The Canvas)

  1. Navigate to the Live Topology Canvas:

    • Here, you will see the Central Manager node, your active Execution Agent nodes (polling), the three registered Database nodes, and the GCS Storage node.

  2. Trigger the Job:

    • Using the action menu, select Execute Policy-> choose Policy A (7-Year Purge)-> aim it at Global Production Systems.

  3. Watch the Orchestration:

    • The Manager instantly fans out 3 distinct job payloads.

    • You will see the visual links illuminate between the Database nodes, the Agent nodes that claimed the work, and the GCS Storage node.

    • Live Metrics: Hovering over the Agent nodes during execution will display real-time counters: Rows Extracted, Bytes Written (Parquet), and Rows Purged.

  4. Validation (The Proof):

    • Once the Canvas shows the jobs as COMPLETED, open a terminal connected to the Source DBs.

    • Run SELECT COUNT(*) FROM orders WHERE order_dt < NOW() - INTERVAL '7 years'.

    • The result will be 0—proving the safe purge was executed.

    • Navigate to Google Cloud Storage. You will see neatly partitioned Parquet files (/orders/, /transactions/) containing the exact records cleanly removed from the operational databases.
